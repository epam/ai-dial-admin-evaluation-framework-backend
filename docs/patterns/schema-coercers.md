# SchemaTypeCoercer vs SchemaChangeCoercer

Two sibling `@Component` coercers in `service.domain.csv`, both `Object coerce(Object value, SchemaFieldType targetType)`, but with **deliberately different rules**. `SchemaTypeCoercer` is permissive — used by **CSV import** where cell strings are ambiguous; allows Integer/Long ↔ Boolean (`!= 0` and `1`/`0`), Boolean → Integer/Number, and any-→ FILE via `String.valueOf`. `SchemaChangeCoercer` is strict — used by **`RevalidationService` after a schema-type change**; drops every "convention-only" rule (Integer/Long ↔ Boolean both directions, Boolean → numeric, Object/Array → STRING, non-String → FILE) so that reinterpreting an existing typed value never silently changes its meaning. `coerceMap(data, schema)` returns a `CoercionResult(coercedData, coercedCellCount, changed)` consumed by the revalidation per-row loop. Always inject the right one for the call site; do not add a "policy" flag.
