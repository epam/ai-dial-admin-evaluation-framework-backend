## 2. Production fix

- [x] 2.1 In `src/main/java/com/epam/aidial/evaluation/client/dialcore/DialCoreDeploymentInvoker.java`, replace the existing `dialCoreTryOutRestClient.method(method).uri(uriBuilder -> { uriBuilder.path(path); uriBuilder.queryParams(queryParams); return uriBuilder.build(); })` site with the explicit-absolute-URI approach (the fallback documented in design.md, activated after empirical verification — see task 1.2): (a) split `path` on `/`, `UriUtils.decode(segment, UTF_8)` each non-empty segment, collecting into `String[] decodedSegments`. (b) Inject `DialCoreProperties` into the invoker; compose `URI uri = UriComponentsBuilder.fromUriString(dialCoreProperties.getBaseUrl()).pathSegment(decodedSegments).queryParams(queryParams).build().encode().toUri();` — a single `encode()` pass over the entire `UriComponents` correctly single-encodes both path segments (preserving sub-delims `(`/`)` per RFC 3986 `pchar`) and query parameter values. (c) Call `dialCoreTryOutRestClient.method(method).uri(uri)` so the configured `UriBuilderFactory` is bypassed and the wire bytes are preserved verbatim. The expected wire literal for an id with a space remains `/v1/deployments/applications/public/Quick%20App%20with%20RAG__0.0.1/route/chat/completions`.
