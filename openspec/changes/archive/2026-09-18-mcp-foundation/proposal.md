## Why

The umbrella change `add-mcp-server` fixes the architecture of the Evaluation Framework MCP server but ships nothing runnable. This first child change delivers the foundation every later tool group builds on: the MCP endpoint itself, security parity with the REST API, the `mcp` layer, the shared result/error/caller plumbing, the functional-test harness, and the first (read-only) tool group, deployments, which agents need before they can create a suite.

## What Changes

- **Build**: root `build.gradle` adds `spring-ai-bom:2.0.1` and `spring-ai-starter-mcp-server-webmvc` (excluding the transitive `spring-boot-starter-web` alias; the project uses `spring-boot-starter-webmvc`). The MCP SDK version hardcoded twice as `mcp-bom:2.0.0` moves to one `gradle.properties` entry `mcp_sdk_version` used by root and `evaluation-runner-core`.
- **MCP endpoint**: Streamable HTTP, sync server, tools capability only, at `spring.ai.mcp.server.streamable-http.mcp-endpoint` (default `/mcp`, set explicitly in `application.yml`, as is `protocol: STREAMABLE`, which Spring AI does not default). Server `name`, `version` and `instructions` (agent workflow guidance) configured in `application.yml`. Disableable with `spring.ai.mcp.server.enabled=false` (endpoint answers 404). The security matcher (below) authenticates the configured endpoint unconditionally, so an operator can switch `spring.ai.mcp.server.protocol` between `STREAMABLE` and `STATELESS` (both serving that same one path) purely via configuration — no startup guard, no code change. The deprecated `SSE` protocol is out of scope and unsupported by the matcher.
- **Caller identity (umbrella D3 assumption verified: it holds, on two library behaviours)**. With Spring AI's servlet autoconfiguration (`type=SYNC`, `immediateExecution(true)`) and the WebMVC streamable transport blocking on the request thread, tool bodies run on the HTTP request thread with `SecurityContextHolder` and `AuthorizationTokenHolder` populated. This change adds no propagation machinery; it verifies the behaviour with a test-scope probe tool **before** any tool is written and records the transport-context capture design as the contingency (design D-F2c).
- **Security**: `SecurityConfiguration` adds `.requestMatchers(mcpEndpoint).authenticated()`, with the endpoint path read from the same Spring AI property (`streamable-http.mcp-endpoint`) that both the `STREAMABLE` and `STATELESS` transports serve, so the matcher cannot diverge from the endpoint Spring AI itself serves regardless of the configured protocol. `NoSecurityConfiguration` already permits everything.
- **New top-level package `com.epam.aidial.evaluation.mcp`** and **new `mcp` layer** in `LayeredArchitectureTest` (`mcp` → `service`, `configuration`, `constants`, `utils`, `client` DTOs, `runner`; never `web` or `data`; only `configuration` may depend on `mcp`).
- **Cross-cutting support (`mcp.support`, `mcp.model`, `mcp.constants`)**: `McpToolResults` (single `text` block JSON encoding), `McpToolErrorTranslator` (full exception → code table, umbrella D7 completed with the `ResourceAccessException` and all `DialCoreErrorCode` branches), `McpErrorCode` + `McpToolError`, `McpToolExecutor` (translation + encoding around every tool body; tools never throw), `McpCallerContext` (JWT or `null`, bearer token; treats `AnonymousAuthenticationToken` as no authentication), `UnsupportedFeatureGuard` + `UnsupportedFeatureException`, `mcp.constants.McpToolNames` / `mcp.constants.McpToolDescriptions` (incl. the literal unsupported-feature sentence) — MCP-only, so they live under the `mcp` root rather than the app-wide `constants` package.
- **First tool group, deployments** (`mcp.tools.deployment.DeploymentTools`): `list_deployments` (optional string filters `type` / `interfaceType`, lean summary shape) and `get_deployment` (full detail, `NOT_FOUND` on unknown id), returning MCP-owned `DeploymentSummaryMcpDto` / `DeploymentMcpDto` mapped by `DeploymentMcpMapper`.
- **Test harness**: `McpFunctionalTestSupport` (MCP Java SDK `McpSyncClient` over `HttpClientStreamableHttpTransport` against the booted app, header injection, raw POST helper), a `tools/list` contract test, `StaticJwtTestConfiguration` (a `@Primary` `TokenDecoderFactory` bean under a different name, winning `securityFilterChain`'s by-type injection over the production bean) for `oidc`-mode tests, and the test-scope probe tool `probe_caller_identity`.
- **Configuration** (documented in `docs/configuration.md`, new subsection `2.6 MCP Server (inbound)`): `spring.ai.mcp.server.enabled`, `stdio`, `name`, `version`, `instructions`, `type`, `protocol`, `request-timeout`, `annotation-scanner.enabled`, `capabilities.tool|resource|prompt|completion`, `spring.ai.mcp.server.streamable-http.mcp-endpoint`, `keep-alive-interval`, `disallow-delete`. No `mcp-server.*` property ships in this change (see Impact).
- **Cross-cutting docs written here** (per umbrella D2/D13): `openspec/config.yaml`, `AGENTS.md`, `docs/key-packages.md`, new `docs/patterns/mcp-server.md` linked from `docs/patterns/README.md`, `openspec/specs/README.md`.
- **Umbrella amendments** (task 5.5): D3 rewritten to record the verified request-thread model and its two dependencies; D2 notes flat `@McpToolParam` parameters instead of `*Input` records; D7 table gains the `ResourceAccessException` row and the remaining `DialCoreErrorCode` values; `mcp-server` spec "Structured tool error contract" gains the binding-layer limitation sentence; umbrella task 2.1 no longer expects `mcp-server.*` properties; statuses of umbrella `mcp-server` / `security` requirements this child satisfies flipped to Implemented with notes.
- **No DB schema changes**, no Flyway migrations, no REST API changes.

**Recorded deviations from the umbrella:**
- Tool inputs are flat `@McpToolParam` method parameters, not one `<Group>*Input` record per tool (umbrella D2). Spring AI binds a record parameter by name as a nested property, which would give agents `{"input": {...}}`; flat parameters produce the flat single object the umbrella spec describes.
- Filter parameters are `String`, not enums: Spring AI's schema generator emits enum constant names while binding honours wire values, and binding errors bypass the structured error contract. Values are validated inside the tool so every error goes through the translator.
- `McpToolResultProperties` / `mcp-server.results.max-rows` and `ResultRowLimiter` ship with `mcp-results`, the first consumer; a property nobody reads would be dead configuration.
- Argument **type** mismatches rejected by Spring AI's binding layer yield Spring AI's plain-text `isError` result, outside the structured error contract; recorded as a limitation for the umbrella spec.
- Server test classes are prefixed `McpServer*` because `McpDeploymentFunctionalTests` etc. already exist for the MCP **client**.

Non-goals of this child (owned by later children or deferred in the umbrella): every other tool group; `SuiteProvisioningService`; MCP Origin/Host validation (`ServerTransportSecurityValidator` stays `NOOP`; bearer authentication protects the endpoint); the deprecated `SSE` protocol (out of scope, unsupported by the matcher); session limits (`maxSessions`, `sessionIdleTimeout`).

## Impact

- **Build**: `build.gradle` (root; Spring AI BOM + starter with exclusion; `mcp_sdk_version` interpolation), `evaluation-runner-core/build.gradle` (interpolation), `gradle.properties` (`mcp_sdk_version=2.0.0`). Spring AI BOM 2.0.1 pins the same MCP SDK 2.0.0; the version must move in lock-step when either is bumped (pattern doc).
- **New packages**: `mcp.model`, `mcp.mapper`, `mcp.support`, `mcp.constants`, `mcp.tools.deployment`. **Major classes**: `McpToolExecutor`, `McpCallerContext`, `McpToolResults`, `McpToolErrorTranslator`, `McpErrorCode`, `McpToolError`, `UnsupportedFeatureGuard`, `UnsupportedFeatureException`, `mcp.constants.McpToolNames`, `mcp.constants.McpToolDescriptions`, `DeploymentTools`, `DeploymentMcpMapper`, `DeploymentSummaryMcpDto`, `DeploymentMcpDto` (+ `DeploymentKind`, `DeploymentInterface` enums with wire-value parsing).
- **Modified**: `configuration.security.SecurityConfiguration` (single-endpoint MCP matcher, `@Value`-injected — no separate properties class), `configuration.JsonMapperConfiguration` (`canRead` override on the custom `JacksonJsonHttpMessageConverter` bean, declining `String.class` — it was intercepting the MCP transport's own `ServerRequest.body(String.class)` read), `architectural.LayeredArchitectureTest` (`mcp` layer), `application.yml` (`spring.ai.mcp.server.*` block), `PostgresFunctionalTests` (new `McpServer*` nested classes), `docs/configuration.md`, `openspec/config.yaml`, `AGENTS.md`, `docs/key-packages.md`, `docs/patterns/README.md`, `openspec/specs/README.md`, `openspec/changes/add-mcp-server/{design.md,tasks.md,specs/mcp-server/spec.md,specs/security/spec.md}`.
- **Services consumed (unchanged)**: `DeploymentService.getAllDeployments(type, interface)`, `DeploymentService.getDeployment(id)`, `AuthorResolver` (probe tool, test scope).
- **Security surface**: one new authenticated endpoint family sharing the REST filter chain. `Api-Key` callers keep REST parity: their principal is a `String`, so the JWT-typed caller is `null` and `createdBy` resolves to `anonymous`, exactly as `@AuthenticationPrincipal Jwt` does for REST today.
- **Operational**: in-memory sessions per JVM (single replica or sticky `Mcp-Session-Id` routing); rollback = `spring.ai.mcp.server.enabled=false`.
- **Risks**: the request-thread model rests on Spring AI's `immediateExecution(true)` customizer and the transport's synchronous `block()`; the probe test fails loudly on a regression and D-F2c is the prepared fix. Spring AI 2.0.x API churn is confined to configuration and the harness (pinned BOM).
- **Rollout**: single release; MCP enabled by default with only read-only tools exposed.
- **Test plan**: unit tests for `McpToolErrorTranslator` (one per table row incl. `ResourceAccessException` URL suppression), `McpToolResults`, `McpCallerContext`, `DeploymentMcpMapper`, `UnsupportedFeatureGuard`, `McpErrorCode`/`ErrorCode` alignment, `McpToolConventionTest`; `LayeredArchitectureTest`; functional tests under `@PostgresFunctionalTests`: probe identity in `none` and `oidc` modes (first), initialize + `tools/list` contract, `list_deployments` / `get_deployment` against the mocked `DialCoreClient`, `VALIDATION_ERROR` envelope for an invalid filter, `NOT_FOUND`, `UPSTREAM_TIMEOUT`, `INTERNAL_ERROR` sanitisation, `oidc` 401 without credentials, `Api-Key` parity, disabled-server 404 in both modes.
