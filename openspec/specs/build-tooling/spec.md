# Build Tooling

## Purpose
This spec defines the project's build-tooling baseline — the contract between the project and the build system that produces its artifacts. It pins the Gradle wrapper version, declares the Java toolchain, requires that every build run is free of Gradle deprecation warnings, and binds the documented version in `AGENTS.md` / `openspec/config.yaml` to the wrapper as the source of truth. The intent is that future tooling bumps have an explicit testable requirement to amend rather than being silent file edits.

Status: **Implemented**

## Requirements

### Requirement: Gradle wrapper pinned to a supported version
The project SHALL pin the Gradle wrapper to **Gradle 9.5 or newer (9.x line)** via `gradle/wrapper/gradle-wrapper.properties`. The wrapper SHALL use the `-bin` distribution. The wrapper jar (`gradle-wrapper.jar`), `gradlew`, and `gradlew.bat` MUST match the pinned distribution — i.e. all four files SHALL be regenerated together via `./gradlew wrapper --gradle-version <version> --distribution-type bin` rather than hand-edited.

Status: **Implemented**

#### Scenario: Wrapper properties point at Gradle 9.5+
- **WHEN** a developer reads `gradle/wrapper/gradle-wrapper.properties`
- **THEN** `distributionUrl` SHALL match `https\://services.gradle.org/distributions/gradle-9\.[5-9]\.?[0-9]*-bin\.zip` or a later 9.x / 10.x release
- **AND THEN** `distributionType` (if present) SHALL be `bin`, not `all`

#### Scenario: Wrapper scripts match the pinned distribution
- **WHEN** the wrapper version is bumped
- **THEN** `gradle-wrapper.jar`, `gradlew`, and `gradlew.bat` SHALL all be regenerated by the `wrapper` task of the new Gradle version
- **AND THEN** their hashes SHALL match the canonical files shipped with that Gradle distribution

### Requirement: Build executes cleanly with no deprecation warnings
Running `./gradlew --warning-mode all clean build` SHALL complete successfully and SHALL NOT emit any Gradle deprecation warning. New deprecations introduced by future Gradle minor versions MUST be resolved in the same change that bumps the wrapper, not deferred.

Status: **Implemented**

#### Scenario: Build is forward-compatible with the next major Gradle release
- **WHEN** `./gradlew --warning-mode all clean build` runs on the pinned wrapper version
- **THEN** the build SHALL succeed with exit code 0
- **AND THEN** the build log SHALL NOT contain any line matching `Deprecated Gradle features were used in this build`

### Requirement: jOOQ codegen output stable across wrapper bumps
The `generateJooq` task SHALL produce byte-identical output in `src/main/java-generated/` regardless of Gradle wrapper version, given the same set of Flyway migrations and the same pinned jOOQ codegen version. A wrapper bump MUST NOT cause `git diff src/main/java-generated/` to be non-empty after regeneration.

Status: **Implemented**

#### Scenario: Codegen output is unchanged after wrapper bump
- **WHEN** a developer bumps the Gradle wrapper and runs `./gradlew generateJooq`
- **THEN** `git diff --exit-code src/main/java-generated/` SHALL exit 0 (no differences)

### Requirement: Documented Java and Gradle versions match the wrapper and toolchain
The Gradle version recorded in `AGENTS.md` (Quick Reference table), `openspec/config.yaml` (Tech Stack section), and the build-tooling image tag in `Dockerfile` SHALL match the version pinned in `gradle/wrapper/gradle-wrapper.properties`. The Java version recorded in `AGENTS.md` (Quick Reference table), `openspec/config.yaml` (Tech Stack section), `README.md`, `.cursorrules`, `docs/dev-setup/jdtls-setup.md`, and the JDK image tags in `Dockerfile` (builder `gradle:<gradle>-jdk25-alpine`, runtime `amazoncorretto:25-alpine`) SHALL match the Java toolchain declared in `build.gradle`. The wrapper is the source of truth for the Gradle version and the `build.gradle` toolchain is the source of truth for the Java version; docs, config metadata, and Docker base images follow both.

Status: **Implemented**

#### Scenario: Single source of truth for Gradle version
- **WHEN** any of `AGENTS.md`, `openspec/config.yaml`, `gradle/wrapper/gradle-wrapper.properties`, or `Dockerfile` is updated to change the Gradle version
- **THEN** the other three SHALL be updated in the same change to match

#### Scenario: Single source of truth for Java version
- **WHEN** the Java toolchain in `build.gradle` is changed
- **THEN** `AGENTS.md`, `openspec/config.yaml`, `README.md`, `.cursorrules`, and `docs/dev-setup/jdtls-setup.md` SHALL be updated in the same change to state the same Java version
- **AND THEN** the `Dockerfile` builder (`gradle:<gradle>-jdk<version>-alpine`) and runtime (`amazoncorretto:<version>-alpine`) image tags SHALL be updated to the same Java version

### Requirement: Java toolchain pinned to JDK 25
The build SHALL declare a Java toolchain of `JavaLanguageVersion.of(25)` in `build.gradle`. The Gradle wrapper version chosen MUST be compatible with executing a JDK 25 toolchain (Gradle 9.6.0 supports this, as evidenced by the published `gradle:9.6.0-jdk25-alpine` build image).

Status: **Implemented**

#### Scenario: build.gradle declares the toolchain
- **WHEN** a developer reads `build.gradle`
- **THEN** the `java { toolchain { ... } }` block SHALL set `languageVersion = JavaLanguageVersion.of(25)`
- **AND THEN** the build SHALL provision a JDK 25 toolchain automatically when the host lacks one

#### Scenario: Build and tests pass on JDK 25
- **WHEN** `./gradlew --warning-mode all clean build` runs with the JDK 25 toolchain
- **THEN** compilation SHALL succeed under the `-Werror` JavaCompile flag with no errors or warnings
- **AND THEN** the full test suite (unit + Testcontainers functional, including `JooqSchemaDriftTest`) SHALL pass

## Implementation notes
- Wrapper files: `gradle/wrapper/gradle-wrapper.properties` (pinned to `gradle-9.6.0-bin.zip` as of 2026-06-19), `gradle/wrapper/gradle-wrapper.jar`, `gradlew`, `gradlew.bat` — regenerated via two consecutive `./gradlew wrapper --gradle-version 9.6.0 --distribution-type bin` invocations (first pass updates `distributionUrl`; second pass, driven by 9.6.0, refreshes the wrapper jar + scripts).
- Build script: `build.gradle` (Groovy DSL) — toolchain block: `java { toolchain { languageVersion = JavaLanguageVersion.of(25) } }`.
- Drift guard: `git diff --exit-code src/main/java-generated/` post-`generateJooq` is the operational check that the codegen output is stable; `JooqSchemaDriftTest` (in `./gradlew test`) is the runtime check that the committed sources match the live schema.
- Tech-stack metadata: `AGENTS.md` Quick Reference table row `| Build | Gradle 9.6.0 |`; `openspec/config.yaml` `# Tech Stack` line `- Build: Gradle 9.6.0`.
- Docker images: `Dockerfile` `FROM gradle:9.6.0-jdk25-alpine AS builder` and runtime `FROM amazoncorretto:25-alpine`. (CI builds via GitHub Actions under `.github/workflows/`, which build through the `Dockerfile` rather than pinning a Gradle image directly.)
